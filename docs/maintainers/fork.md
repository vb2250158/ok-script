# 本仓库的分支与开发方向

本仓库基于 [ok-oldking/ok-script](https://github.com/ok-oldking/ok-script)，复用官方 Python 自动化运行时和 Agent/MCP 开发流程。自有扩展聚焦录屏演示，帮助 AI 理解用户希望完成的任务。

## 活跃分支

| 分支 | 用途 | 当前状态 |
| --- | --- | --- |
| `master` | 官方主线同步及已合入本 fork 的通用修复 | 已合入 2026-11-11 的官方提交 `f86ce60`，保留 UTF-8 BOM 配置读取与损坏配置备份修复 |
| `codex/screen-recording-annotation` | 录屏、点击与拖拽事件、关键帧和标注素材 | 保留现有实现，当前基于官方提交 `6814e65`；适配官方新版 Qt 界面待完成 |

录屏功能在独立分支中。`master` 沿用官方界面与运行入口，尚未集成录屏扩展。

## 录屏扩展的目标

希望用户演示一次日常操作后，AI 能利用演示素材开发、验证并保存可重复运行的 Python 任务。支持两类演示输入的设计目标：

- 用户直接提供已有视频，由 AI 分析操作过程。
- 在工具中录屏，同时保存带时间信息的点击、拖拽事件。

现有实现已经包含工具录屏、操作事件、关键帧、标注和模板导出。普通视频导入、统一的 Agent 素材交接，以及从演示到已验证任务的完整流程仍待开发；提供录屏本身尚不能保证每日任务已经生成或通过验证。

## 已停止的方向

行为树和可视化流程编辑器停止开发。历史实现及更新前快照已保存在本地恢复归档中，不作为活跃分支继续同步。

后续任务直接复用官方 Python 任务、MCP 调试、模板生成与回归验证入口。录屏扩展不再生成行为树或维护第二套任务运行时。

## 仓库维护

- 更新 `master` 时保留本 fork 的有效修复，使用正常合并，避免覆盖远端历史。
- 录屏分支按独有功能接入官方扩展入口；适配新控件后再更新其兼容状态。
- 录屏、账号配置、游戏截图、运行日志、恢复归档和本地环境留在仓库外或被忽略的数据目录中。
- 仅在明确发布版本时创建发布标签；日常分支整理不发布软件包。
